# Пыль и порох — Unity-прототип

Проект по согласованному ТЗ: фиксированные персонажи, скрытые роли, два общих такта исполнения, онлайн-комнаты и боты. Создан на установленном Unity 6000.6.4f1. Это ранняя игровая версия для проверки механик, с собственной процедурной графикой и звуковыми эффектами.

## Быстрый запуск

**Windows:** откройте `Builds/Windows/DustAndPowder.exe`, нажмите «Играть с ботами». Сервер и интернет для этого режима не нужны.

**Unity:** добавьте эту папку через Unity Hub → Add project from disk, откройте `Assets/Scenes/Main.unity`, нажмите Play. Точка входа создаётся автоматически через RuntimeInitializeOnLoadMethod.

**Браузер:** из корня проекта выполните `node Tools/serve-web.mjs`, затем откройте http://127.0.0.1:8080. Нельзя запускать index.html непосредственно через file://. Нужен Node.js; тесты сети используют встроенный WebSocket Node.js 22 или новее.

## Как играть

1. Прочитайте роль и цель под сценой. Шериф открыт, чужие руки и остальные роли скрыты.
2. Выберите слот «Такт 1» или «Такт 2» и карту в руке. Для выстрела, кражи и разоружения нажмите подсвеченную цель.
3. Карты уклонения добавляются в резерв одним нажатием; до двух карт. Удалить действие или резерв можно кнопкой ×.
4. Нажмите «Подтвердить план». После этого план заблокирован. Если таймер истёк, выполняется последний сохранённый допустимый план.
5. Все исполняют первый такт вместе, затем второй. Лечение, экипировка и разоружение предшествуют выстрелам; урон применяется одновременно.
6. В каждом раунде разрешена одна атака, включая залп. Карты, полученные при исполнении, используются со следующего раунда.
7. ПКМ по карте добавляет или снимает её приоритет итогового сброса. При отсутствии выбора сбрасываются самые старые карты сверх лимита.
8. Для сигнала «Подозрение» сначала выберите персонажа, когда карта атаки не выбрана. Сигналы не раскрывают роль.

С раунда 16 растёт истощение. Все партии завершаются не позднее раунда 26. Подробности — `Docs/TZ_igry_v0.1.md`.

## Онлайн на одном компьютере

1. Запустите PowerShell-скрипт `Server/start-server.ps1`. Он использует .NET 8 SDK из PATH либо поставляемый с установленным Unity SDK.
2. Откройте две Windows-копии игры или две браузерные вкладки.
3. Адрес подключения: `ws://127.0.0.1:8081/ws`.
4. Первый игрок создаёт комнату, второй вводит код. Все люди нажимают «Я готов», владелец — «Начать матч». Незанятые места заполняются ботами.
5. При разрыве соединения клиент пытается вернуться на своё место в течение 60 секунд. Полная перезагрузка страницы сбрасывает текущий токен; сохранение сеанса между перезагрузками пока не реализовано.

Онлайн использует авторитетный сервер. Боты не получают чужие руки, скрытые роли или будущую колоду. Клиенту передаются только личное состояние и публичные события.

## Онлайн через интернет и itch.io

Сборка клиента подготовлена в `Builds/Web` и архиве `Builds/DustAndPowder-itch.zip`. На itch.io выберите HTML Game, загрузите ZIP и включите запуск в браузере; index.html находится в корне архива.

Для удалённого мультиплеера нужен отдельно запущенный сервер с публичным адресом WSS. Его контейнер описан в `Server/Dockerfile`: `docker build -f Server/Dockerfile -t dust-and-powder .`. В контейнере используется порт 8081. TLS завершается на reverse proxy перед сервером; proxy должен поддерживать WebSocket Upgrade. Проверка здоровья — GET /health.

Задайте `BANG_ORIGINS` списком разрешённых источников через запятую. Для itch.io добавляйте именно origin iframe, из которого запускается сборка, а не только адрес страницы проекта. Затем в меню клиента укажите `wss://ваш-домен/ws`. Сервер по умолчанию принимает браузерные подключения только от localhost:8080 и 127.0.0.1:8080.

Сервер ещё не развёрнут в интернете; проект и архивы не опубликованы на itch.io. Публичный TLS, ограничения reverse proxy, работа реального iframe itch.io и сетевые задержки между удалёнными игроками требуют отдельной проверки после развёртывания.

## Сборка

`Tools/build.ps1 -Target Windows` и `Tools/build.ps1 -Target Web` вызывают Unity в batchmode. Если редактор установлен иначе, передайте путь параметром `-Unity`. Закройте редактор проекта перед запуском сборки. Журналы — `Logs/Windows.log` и `Logs/Web.log`.

## Проверки

- `dotnet run --project Tests/Bang.Tests.csproj`: сценарии одновременного урона, лечения, защиты, экипировки, кражи, победы, истощения; 400 полных симуляций и сравнение повторов.
- При запущенном сервере: `node Tools/test-network.mjs` — два клиента, приватность, блокировка плана, переподключение и два такта.
- `node Tools/test-load.mjs` — 20 комнат, 140 соединений, два такта и приватность рук.
- Результаты и ограничения проверки — `Docs/VERIFICATION.md`.

## Структура

- `Assets/Scripts/Core` — общие правила, боты, формат сообщений; без Unity API.
- `Assets/Scripts/Client` — интерфейс, графика, анимации, локальная сессия и транспорт.
- `Assets/Plugins/WebGL` — браузерный WebSocket-мост.
- `Assets/Editor` — подготовка сцены и сборка.
- `Server` — .NET 8 сервер комнат, таймеры, команды и приватные представления.
- `Tests` — автоматические проверки правил без Unity.

## Известные ограничения

Процедурные персонажи и короткие анимации подходят для прототипа; финальные иллюстрации, музыка и полноценная постановка боя ещё требуют производства. Нет открытого матчмейкинга, аккаунтов и рейтинга. Падение процесса сервера прерывает матчи; постоянное хранение и восстановление после рестарта не реализованы. Настройки сервера и все действующие комнаты хранятся в памяти. Нет выбора количества ботов в лобби: они автоматически заполняют свободные места до выбранного размера комнаты.
